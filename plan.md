1. End-to-End 6-Stage System Architecture

Stage 1: Pre-Match Roster Manifest & Normalization (Ground Truth)Never treat live kill detection as open-ended text reading—treat it as a closed-set classification problem against the 48 known players in the lobby.Structured Lobby Manifest: Before drop, load a JSON manifest mapping every team_id (1–12) to its team_name, team_tag, and up to 4 players.ASCII Skeleton Indexing: For every player, store both their raw in-game name (IGN) and a stripped normalized skeleton (removing decorative Unicode symbols, invisible spaces, and stylistic borders while retaining core alphanumeric characters and clan prefixes).Lobby Slot Calibration: Capture one clean frame of the pre-match custom room roster or spectator squad list to verify how the game font renders ambiguous glyphs (0 vs. O, 1 vs. l vs. I).

Stage 2: High-Signal Video Ingestion & ROI BlueprintCapture at the Source:
 Ingest directly from the observer PC via OBS Virtual Camera, NDI, or local RTMP at 1080p rather than scraping a re-compressed YouTube stream. Eliminating platform compression alone cuts OCR character errors dramatically.Smart Frame Sampling (4–5 FPS): A Free Fire kill-feed entry remains visible for roughly 3 to 5 seconds. Sampling every 200–250 ms guarantees at least 12–20 observations per kill while keeping CPU load low enough to run smoothly without a high-end GPU.Coordinate Blueprint Masking: Following production esports CV pipelines like PandaScore, crop every frame to strict, resolution-normalized Regions of Interest (ROIs):   ROI A (Kill-Feed Zone): Isolates the notification rows where eliminations appear.ROI B (Alive Counter): Tracks the global Alive count as an independent sanity check.ROI C (Game-State Guard): Detects replays, lobby screens, or caster transitions so the parser automatically pauses and never counts replayed kills.

Stage 3: Change-Gated Row Parsing & Icon ClassificationRunning OCR on every frame wastes compute and creates noise. Instead, gate and segment each row structurally:Pixel Diff Gate:
 Compare ROI A against the previous sampled frame using Structural Similarity (SSIM) or fast grayscale differencing. Skip inference completely when the kill feed is static (cuts processing load by 70–85%).Row Segmentation: Slice ROI A into fixed horizontal banner strips (typically 3–5 active slots).Weapon & Action Icon Detection (The Accuracy Multiplier): Run a lightweight custom-trained YOLOv11-nano (ONNX) model or fast template/color classifier over each strip to locate the center action icon. This solves two critical problems simultaneously:Knock vs. Elimination Filtering: Immediately discards Knocked Down banners and only passes confirmed eliminations (skull, headshot, weapon kill, grenade, vehicle, zone).Exact Left/Right Splitting: Uses the icon bounding box's horizontal edges (x_min, x_max) to crop [Left = Killer] and [Right = Victim] cleanly. Because the two names are never OCR'd in the same crop, they can never bleed into each other.Targeted Pre-Processing: Upscale each name crop 2x–3x (bicubic), convert to grayscale, apply CLAHE contrast normalization, and apply adaptive thresholding to separate bright HUD text from bright explosions or sky textures.

Stage 4: OCR & Roster-Constrained Fuzzy MatchingOCR Engine:
 Use RapidOCR (ONNX Runtime) or PaddleOCR (PP-OCRv5/v6). Both outperform Tesseract significantly on stylized game fonts and run in ~15–40 ms per small crop on a standard CPU.   Fuzzy Matching Pipeline: Strip non-alphanumeric noise from the raw OCR output and score it against all 48 player skeletons using RapidFuzz (combining partial_ratio and WRatio).Three-Tier Confidence Routing:At least 85% match score: Auto-accept candidate event.65% to 84% match score: Hold in the temporal buffer for multi-frame consensus (often resolves to 90%+ one frame later once the fade-in animation finishes).Less than 65% match score: Route the cropped image snippet to the Referee Dashboard for 1-click verification.Edge-Case Rules: If the Left Crop is empty or matches environment terms (Playzone, Fall, Eliminated), record killer_id = NULL (victim dies, zero kill points awarded). Always verify killer.team_id != victim.team_id to prevent self-elimination or misread self-kills from inflating a team's total.

Stage 5: Temporal Consensus & Revival-Aware DeduplicationThis stage guarantees zero double-counting and zero ghost kills:Multi-Frame Voting (3-Frame Consensus):
 Never commit a kill from a single frame. Track candidate (killer_id, victim_id) pairs across a rolling 1.2-second window. Only emit a confirmed KILL_EVENT once the exact pair achieves consensus in at least 2 of 3 consecutive samples. This eliminates mid-scroll clipping and single-frame motion blur errors.Revival-Aware Cooldown Window: Because Free Fire allows knocked/eliminated players to return via Revival Points or Vending Machines, you cannot lock a player as "permanently dead" for the rest of the match. Instead, store a deduplication hash H(killer_id, victim_id) with a 15-second sliding cooldown.15 seconds is comfortably longer than a kill banner's ~4–5 second on-screen lifespan (preventing duplicate counts).It is safely shorter than the time required to revive, drop back in, and get eliminated again by the exact same killer.Global Alive Cross-Check: Maintain an internal count of living players. If the HUD Alive counter (ROI B) diverges from your internal elimination count for more than 5 seconds without a revival spike, trigger a subtle amber alert on the admin console.

Stage 6: Event-Sourced Ranking Engine, OBS Overlay & Referee Fail-SafeEvent-Sourced Ledger (Zero State Drift): 
Never store team kills solely as mutable counters (team.kills += 1). Store every kill as an immutable timestamped event row (event_id, timestamp, killer_id, killer_team_id, victim_id, victim_team_id, confidence, status). Compute the live leaderboard dynamically by aggregating all ACTIVE events. If you ever undo or reassign a kill, every team's total and rank recalculates cleanly with zero math drift.Deterministic Ranking & Tie-Breakers: Sort teams in real time by:total_kills (descending) — or easily extensible to full Free Fire tournament scoring (placement_points + kill_points).   alive_players (descending — active teams edge out eliminated teams on equal kills).first_to_reach_timestamp (ascending — the team that reached that kill count earlier holds the higher rank).Real-Time Broadcast Overlay: Push state diffs over WebSockets to a transparent HTML/React page loaded directly as an OBS Browser Source (1920x1080, 30 FPS) for smooth animated row reordering, live kill counters, and eliminated-team styling.1-Click Referee Dashboard (The 100% Guarantee): Professional esports broadcasts never run 100% blind. Pair the automated pipeline with a lightweight web console that displays the live kill log alongside the cropped kill-feed thumbnail for any event under 85% confidence, offering instant Confirm / Reassign Killer / Undo controls. Because live streams typically carry a 10–30 second broadcast delay, any rare OCR ambiguity can be corrected before viewers ever see the leaderboard update.
